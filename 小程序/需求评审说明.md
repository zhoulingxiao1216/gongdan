# 质控报工小程序 · 附加项报工首版需求与原型说明

版本：V0.1 / 2026-09-10。交付：`index.html`，无后端、无依赖、可直接用浏览器打开。

本文按“需求理解—页面结构—核心流程—逐页设计—可视化原型—需求核对”组织。文件均为 Markdown，无固定页码，使用章节定位。所有示例商品、员工、订单、标签均为虚构。

## 一、需求理解

### 1.1 依据与优先级

| 代号 | 依据 | 本次用途 |
|---|---|---|
| U | 用户本轮 5 条确认 | 本版范围与规则的最高优先级 |
| P | 《商品ID二维码报工与QCVAS数字化初版PRD-20260905》 | §5 角色；§10.5 附加项规则；§11.3 页面；§12 异常；§13 数量；§18 待确认 |
| I | 《PDA四工作台交互规约-20260905》 | §1–2 通用交互；§5 附加项报工 |
| L | 《PDA四工作台原型设计说明与页面布局规约-20260905》 | §1 字号、触控与状态；§4 附加项布局和字段 |
| A | 《建议A-商品ID二维码报工第一版初稿-20260905》 | 商品 ID 驱动、保留原岗位分工与纸质流转的背景 |
| E | 《质检与附加服务系统评估改善方案-20260905》 | §3.4 打印与实体完工边界；§4.1.2 工票；§6 幂等、防错及分期建议 |

规则标签：**[文件明确]** 指文件写明；**[用户确认]** 指 U 覆盖或补充；**[合理推断]** 为使首版可用所作假设；**[建议新增]** 为本次设计建议，不视为已确认需求。

### 1.2 产品目标与角色

小程序暂名“质控报工”：[合理推断]，文件提供了业务定位，未明确品牌名称。

目标：[文件明确 P§2、§3、§11.3] 将附加项的纸面勾选、手写工号转为“商品—项目—数量—实际处理人—时间”的报工记录，能立即知道每项应做、已报、剩余。

用户：[用户确认 U1、U5] 初检、质检、尾检及实际附加项处理人员均可使用，不做岗位权限划分。仅附加项工作台实现核心操作，初检、质检、尾检预留入口；不在本版替前序岗位改数量或替尾检放行。

核心场景：人员扫描商品流转单 → 核对商品与最新正品数 → 预览所需标签 → 选择一项服务 → 填写本次完成数量并确认处理人 → 提交 → 查看剩余与记录 → 继续当前商品或扫下一商品。

### 1.3 首版范围

| 分类 | 内容 |
|---|---|
| 本版实现 | 工作台入口、模拟扫码/手输、商品摘要、已配置附加项、逐项报工、四类预览、数量校验、增量重新开放、报工结果、记录追溯 |
| 本版辅助 | 图片凭证、商品筛选、未提交退出确认、失败重试、评审用数量更新和并发模拟 |
| 仅预留 | 初检、质检、尾检工作台 |
| 本版不实现 | 真实微信登录/扫码、真实标签文件/打印、退换货办理、上游正品编辑、尾检操作、工单闭环、计件工资、计费金额、SKU/套计量、离线同步、管理看板 |

### 1.4 数量规则与动态正品

**本版核心：每个附加项独立累计，后续提交记录的是本次新增完成量。**

定义：G = 上游最新可处理正品数；Dᵢ = 当前商品当前附加项累计成功报工数；Rᵢ = 该项剩余可报数；q = 本次提交数量。

```text
本版应做数 = G                         [合理推断：已配置项目覆盖全部当前正品]
Rᵢ = max(0, G − Dᵢ)                  [用户确认 U2]
q 必须为正整数，且 q ≤ Rᵢ              [文件明确 P§10.5 + 合理推断整数件]
成功后：Dᵢ' = Dᵢ + q                  [文件明确：允许分次报工，累计受限]
正品增加：更新 G，保留 Dᵢ，重新计算 Rᵢ  [用户确认 U2]
```

每个项目有独立上限。例如 7 件正品可以分别报贴纸 7 件、吊牌 7 件；两项合计 14 作业件次不属于超报，不能用所有项目总和与 7 比较。

| 状态 | 正品 G | 贴纸累计 D | 剩余 R | 用户行为 |
|---|---:|---:|---:|---|
| 初始 | 7 | 5 | 2 | 本次最多填 2 |
| 补报成功 | 7 | 7 | 0 | 数量已报齐，不可重复报 |
| 退换货处理后上游增加正品 | 9 | 7 | 2 | 重新开放 2 件，不需要重做旧记录 |
| 增量报工成功 | 9 | 9 | 0 | 新增一笔 +2，历史仍可追溯 |

其他口径：

1. [用户确认 U2] 只处理正品；待定、不良不作为报工基数。商品数量由上游更新，本版人员无“修改正品数”操作。
2. [用户确认 U3] 暂不区分 SKU、套；所有项目均按普通计费口径、数量报工，原型单位统一为“件”，不展示价格。
3. [用户确认 U4] 贴纸、吊牌、洗标、FBA 均支持预览。[合理推断] 预览是辅助核对动作，不强制“看过才能报”；不等同双扫码验证。
4. [文件明确 P§10.5、I§5] 仅可报订单配置的项目；累计已报齐置灰。[用户确认 U2] 置灰必须可随正品增量解除，不能永久锁死。
5. [文件明确 I§5] 实际处理人必填。[合理推断] 默认演示登录人，可选另一位演示人员；每次提交前勾选确认，换人后重新确认。不因角色拦截。
6. [文件明确 I§5] 贴纸、吊牌已报部分仍提示“待尾检复核”。[合理推断] 洗标/FBA 暂不额外继承该强制规则。
7. [建议新增] G 小于任一项目累计 D 时，保留记录并暂停该商品所有项目报工，联系负责人核对；不自动删历史或生成负数报工。
8. [建议新增] 表单打开后发生上游更新或他人报工，提交时复查最新 G、D；发现变化先刷新并要求再核对一次，仍有合法剩余才允许提交。
9. [合理推断] 拍照项需一张图片凭证，其他项目选填。初版演示限 JPG/PNG/WebP、2 MB；这是原型假设，不是用户确认的正式上传规格。
10. [建议新增，参考 E§6] 同次提交处理中锁定输入和按钮，避免连点；真实服务端仍需幂等与原子数量检查，前端演示不能替代这些保障。

| 编号/页面 | 用途 | 入口 | 上级/返回 | 跳转目标 |
|---|---|---|---|---|
| P01 工作台 | 显示人员，进入附加项 | 启动、底部工作台 | 一级页 | P02、P07、P09 |
| P02 扫描商品 | 扫商品码或手输 ID | P01、下一商品 | P01 | P03；模拟扫码弹层 |
| P03 商品与附加项 | 核对商品、进度、选择任务 | 查询成功、继续当前商品 | P02 | P04、P05、P07、P02 |
| P04 填写报工 | 当前单项数量、人员、凭证 | P03 去报工 | P03，脏表单确认退出 | P05、P06 |
| P05 标签预览 | 四类共用预览页 | P03 预览、P04 查看预览 | 返回原入口并保留表单 | P03 或 P04 |
| P06 报工结果 | 确认成功、选择后续任务 | P04 成功 | P03 | P03、P02、P08 |

弹层：模拟扫码选择、取消填写确认、重置演示确认、移动端评审工具。它们不是独立业务页面。

## 三、核心操作流程

### 3.1 主流程

```text
启动 P01 工作台
  → 扫码开始报工 P02
  → 模拟扫 VAS/DDEMO001 或手输 DDEMO001
  → 查询中 → 匹配商品 P03
  → 查看当前正品 7、贴纸累计 5、剩余 2
  → 预览贴纸 P05 → 返回 P03
  → 贴纸「去报工」P04
  → 「完成当前剩余 2 件」→ 确认实际处理人
  → 提交中（锁定表单）→ 报工成功 P06
  → 继续当前商品 P03 / 下一商品 P02 / 本次记录 P08
```

### 3.2 正品增量流程

上游退换货处置形成正品增加（本版不办理处置）→ 商品最新正品 7→9 → 每项保留累计已报值 → 原先贴纸已报齐 7，当前剩余变为 2 → 报工按钮重新开放 → 新增一笔 2 件 → 明细保留各次提交的正品数量快照。

电脑右侧“评审演示台”可模拟这次更新；手机窄屏从工作台或商品页“评审”入口进入。它不是员工编辑正品数的入口，正式产品应移除。

### 3.3 分支与反馈

| 分支 | 反馈/去向 | 数据处理 |
|---|---|---|
| 取消扫码 | 留在 P02，“已取消扫码” | 不产生记录 |
| 空 ID / 扫错码 | 行内提示输入商品 ID，不支持快递单号 | 不查询、不报工 |
| 商品不存在 | “未找到商品，请检查商品 ID 后重新查询” | 留在 P02，可重试 |
| 无附加项 | P03 显示“无需附加项” | 不伪装成所有任务已完成；可下一商品 |
| 无正品 | P03 显示等待质检结果或数量更新 | 项目可查看，不能报工 |
| 超报/小数/零/负数 | P04 行内错误，提交禁用 | 不写记录 |
| 未确认处理人 | P04 提示确认实际处理人 | 不写记录 |
| 已填表返回/取消/跳页 | 弹层“继续填写 / 放弃并离开” | 继续保留；放弃仅清未提交表单 |
| 预览返回 | 回到原页面与原滚动位置 | 保留报工数量、人员、凭证 |
| 提交失败 | P04 “本次未写入记录，内容已保留” | 可重新提交；本演示失败不写入 |
| 提交中重复点击 | “正在提交”，禁用输入与提交 | 仅一个提交过程 |
| 别人先报工/正品更新 | 刷新剩余，提示复核再提交 | 旧快照不直接入账 |
| 预览失败 | P05 重新加载 | 不改变报工数 |
| 预览未生成 | P05 联系设计/打印人员，刷新 | 不冒充文件已存在 |
| 正品减少且累计超出 | P03 红色数量待核对 | 保留历史，暂停报工 |
| 记录筛选无结果 | P07 “暂无报工记录”，可开始报工 | 不显示无关商品记录 |

## 四、逐页原型设计

### 4.0 共用设计与状态

沿用 L§1、§4 的窄屏、纵向、大数量、底部固定操作结构，将原 PDA 同屏列表+表单拆为“商品任务页+单项填写页”。这是适配微信小程序、减少中老年用户一次阅读量的[合理推断]，不是改变业务步骤。

普通文字 16px 左右，辅助说明 14px，关键数量 28–34px，主按钮高 56px，次按钮至少 46px。深绿色主动作、黄色待处理、红色异常、灰色不可操作；状态同时用文字表达，不只依赖颜色。统一顶部返回与页面标题，主体滚动、操作区固定。

权限不足：U5 明确首版不划分权限，所有页面均 **不适用岗位权限不足状态**。预留入口不是权限错误。真实微信登录失败、摄像头授权拒绝留在后续接入范围，不伪装成原型已实现。

### P01 工作台

- **目标**：一眼找到附加项报工入口，确认当前演示人员。
- **布局（上→下）**：导航 → 演示人员/小组 → 附加项主入口 → 记录汇总 → 三个预留工作台 → 底部 tab。
- **字段/示例**：演示员工 V026；报工笔数；作业件次；涉及商品数。作业件次按不同项目累计，不是实际商品数，也不计算工资。
- **按钮**：“扫码开始报工”→P02；“查看记录”→P07；初检/质检/尾检→P09；底部工作台/报工记录切一级页。
- **必填/校验**：无表单。统计来自已成功保存的模拟记录。
- **状态**：初始带 2 笔模拟历史；成功后统计更新。独立网络加载/错误不适用，因为无后端。权限状态遵循共用规则。

### P02 扫描商品

- **目标**：以商品 ID 定位作业，不要求查订单。
- **布局**：导航 → 扫码指引 → 模拟扫码按钮 → 手动输入卡片 → 查询错误提示 → 测试样本说明。
- **组件/字段**：商品 ID 文本输入；支持 `DDEMO001`、`VAS/DDEMO001`；示例码均虚构，不沿用文件里的实际形似生产编号。
- **按钮**：“模拟扫码”→结果选择弹层；“查询商品”→加载→P03；弹层取消→留在原页；返回→P01。
- **必填/校验**：手输不能为空，trim 后转大写；原型仅匹配三件模拟商品。格式不符提示“请扫描商品 ID 或 VAS 码，不支持快递单号”。真实码解析应由正式接口定义。
- **状态**：等待扫码；查询中；已匹配；未找到；格式错；取消。不存在真实摄像头授权流程；权限不足不适用。

### P03 商品与附加项

- **目标**：确认当前商品、最新基数和每项剩余，选择一个任务。
- **布局**：导航 → 商品摘要卡 → 正品更新/冲突提示 → 已配置任务列表 → 数量规则说明 → 固定“刷新数量 / 下一商品”。
- **字段/示例**：DDEMO001、基础款圆领短袖、黑色/L/单件、订单 DEMO-260910-001；正品 7；贴纸应做 7、已报 5、剩余 2；剪标已报 7。
- **组件**：按项目独立展示任务卡与进度。贴纸、吊牌、洗标、FBA 各有预览入口，即使数量已报齐也可继续查看预览。已报齐项目仍可见，报工按钮灰色。
- **按钮**：“去报工”→P04；“预览××”→P05；“报工记录”→P07 并带商品筛选；“刷新数量”→重新计算；“下一商品”→P02。
- **必填/校验**：只读页面，无用户输入。剩余为 0 或存在正品减少冲突时禁用报工；未配置项目不出现。
- **状态**：待处理、部分完成、数量已报齐、已报部分待尾检复核、正品增量后重新开放、无附加项、无正品、数量待核对。加载由 P02 覆盖；本版刷新无网络错误。岗位权限不足不适用。
- **范围说明**：没有提供源商品图片，本版用商品名称/规格核对，不伪造商品照片；真实商品图片及放大是尚未覆盖的文件细节。

### P04 填写报工

- **目标**：只填写当前单项的本次新增完成量。
- **布局**：导航 → 商品摘要 → 当前附加项/预览 → 正品/累计/本次最多 → 大字号数量步进器 → 一键剩余 → 实际处理人 → 确认勾选 → 凭证 → 行内错误 → 固定取消/提交。
- **字段/示例**：贴纸；当前正品 7、累计已报 5、本次最多 2；本次数量默认空；处理人默认演示员工 V026；确认默认未勾选。
- **按钮**：“− / +”调整数量；“完成当前剩余 2 件”填 2；“查看预览”→P05，返回保留表单；“取消”→脏表单确认后 P03；“提交报工”→处理中→P06。
- **校验**：数量必填正整数且≤最新剩余；人员必选且确认；拍照项图片必填，其他项选填；文件类型/大小符合 1.4 假设。每次输入就展示首个错误并禁用提交。
- **提示**：“请输入大于 0 的整数”“本项最多还能报 2 件，请修改本次数量”“请选择实际处理人”“请确认实际处理人”“请上传本次拍照凭证”。
- **状态**：空表单、可提交、数量错误、人员缺失、凭证错误、提交中、失败保留、最新数量冲突、成功跳转。处理中不允许编辑或跳转；岗位权限不足不适用。

### P05 标签预览（贴纸/吊牌/洗标/FBA 共用）

- **目标**：报工前后可查看对应标签内容，与商品规格核对。
- **布局**：导航 → 商品摘要 → 标签类型/示例版本 → 核对提示 → 内容画布 → 缩小/比例/放大 → 模拟文件说明 → 固定返回。
- **字段/示例**：贴纸 DEMO-SKU-BLK-L；吊牌 DEMO-TAG-001；洗标 DEMO-CARE-001；FBA DEMO-FBA-001。标签均标记“DEMO · 非生产文件”，条码图形与打印尺寸待真实文件接入。
- **按钮**：“放大/缩小”在 75%–200% 展开示例内容，可横向滚动；“重新加载/刷新预览”重试；返回原商品页或表单，不新增报工、不改变已报状态。
- **必填/校验**：无表单，不强制预览完成，不实施双扫码拦截。不提供打印操作。
- **状态**：加载中、内容正常、加载失败、文件未生成。预览成功只代表内容可查看。岗位权限不足不适用。
- **实装要求 [合理推断]**：后续用商品+附加项定位已批准的预览文件和版本，支持图像/PDF；不得将本演示文本当成真实标签模板。

### P06 报工结果

- **目标**：明确提交已成功，以及本次增加多少、下一步做什么。
- **布局**：导航 → 大字成功反馈 → 本项新增数量 → 商品/人员/时间/记录号 → 最新正品/累计/剩余 → 待尾检提示 → 查看记录 → 固定下一商品/继续当前商品。
- **字段/示例**：贴纸 +2 件，累计 7、剩余 0；记录号 DEMO-R003。
- **按钮**：“继续当前商品”→P03；“下一商品”→P02；“查看本次记录”→P08。
- **必填/校验**：无。仅成功后进入；失败不出现成功页。
- **状态**：成功，必要时叠加待尾检复核。报工成功不等于入库放行。其他错误/权限状态不适用。

### P07 报工记录

- **目标**：核对每次报工流水，确认增量没有覆盖历史。
- **布局**：导航 → 说明 → 商品筛选 → 笔数/作业件次 → 倒序记录卡 → 底部 tab。
- **字段/示例**：贴纸 +2 件、DDEMO001、演示员工 V026、提交时间；默认所有演示人员，无权限分流。
- **按钮**：商品筛选即时更新；“查看详情”→P08；“开始报工”→P02；工作台 tab→P01。
- **必填/校验**：筛选可选全部商品，不必填。
- **状态**：有记录；筛选无记录（如 DDEMO002）；报工成功后新增。记录来自本地模拟，没有独立网络加载/错误。权限不足不适用。
- **范围**：按日期/员工筛选、导出、管理报表未实现，避免扩大首版范围。

### P08 报工详情

- **目标**：展示一笔不可被增量更新覆盖的事实记录。
- **布局**：导航 → 成功状态 → 项目和本次数量 → 记录号/商品/实际处理人/时间 → 提交时正品数量快照与记录类型 → 凭证或无凭证说明 → 返回记录列表。
- **按钮**：“返回记录列表”或顶部返回→P07。
- **必填/校验**：只读，不提供修改、删除、冲销。
- **状态**：有效记录正常；无凭证显示“本次未附凭证”；无当前记录回到列表。无网络加载与岗位权限错误。

### P09 其他工作台预留

- **目标**：让评审看见后续扩展位置，又不误认为已经实现。
- **布局**：导航 → 首版预留标签 → 对应岗位工作台名称 → 本版未实现说明 → 返回工作台。
- **按钮**：仅“返回工作台”→P01。
- **必填/校验**：无。
- **状态**：固定未开放态，不是权限不足，不提供虚假的初检提交或尾检放行。

## 五、可视化原型

### 5.1 文件与打开方式

同目录 `index.html` 是完整单文件原型，双击或用现代浏览器打开即可，无安装、构建、后端依赖。电脑显示“页面导航 + 小程序手机框 + 评审演示台”；窄屏显示全屏小程序。

模拟数据尝试保存在浏览器 localStorage；同浏览器同文件可继续演示。若浏览器限制本地文件存储或存储已满，仅本次打开期间有效。刷新不承诺保留未提交表单。页面内“重置全部演示数据”可恢复初始状态；不触碰原始需求文件。

### 5.2 三组快速走查

**A. 增量主线**：扫码 DDEMO001 → 贴纸补报 2 → 继续当前商品 → 评审台正品 +2 → 贴纸剩余重新为 2 → 再报 2 → 记录列表出现两笔新增，历史 5 保留。

**B. 四类预览**：商品页分别进入贴纸/吊牌/洗标/FBA → 放大/缩小 → 返回；在贴纸填写页填数量后预览再返回，表单保留。评审台可选择预览失败或文件未生成后再次打开预览。

**C. 防错分支**：贴纸剩余 2 时填 3 → 提交禁用；正确填写但未确认处理人 → 禁用；设置提交失败 → 内容保留、记录不增加 → 重试只增加一次；模拟他人报当前项 +1 → 剩余复查；模拟正品减少到 4 → 暂停报工。扫码 DDEMO002/DDEMO003 观察无附加项/无正品状态。

### 5.3 验证范围

已执行 JavaScript 数量函数自检：上限、增量重新开放、累计超报、已报齐防重复、非法数字、人员确认、正品减少冲突与拍照凭证规则。另执行使用最小 DOM 替身的页面渲染与业务状态测试，结果见 `验证记录.md`。

当前受控浏览器工具返回“没有可用浏览器”，因此未完成真实浏览器截图验收、触屏体验和微信客户端验证；不将逻辑测试描述为实际浏览器点击测试。HTML 提供完整交互，可由评审人员直接打开走查。

声音/震动、扫码硬件、真实图片/PDF预览、跨设备同步、服务端并发事务与正式幂等均未接入。本版只提供屏幕文字反馈；文件中硬件反馈要求列入后续接入项。

### 6.3 设计假设与待评审建议

| 分类 | 当前处理 | 后续影响 |
|---|---|---|
| 合理推断 | 名称“质控报工”，每项应做量等于全部最新正品 | 若有部分商品才做某项，需引入项目独立应做数量与上限规则 |
| 合理推断 | 所有项目统一按正整数件数 | SKU/套计量未来需按项目配置单位与换算，不回改历史单位 |
| 合理推断 | 实际处理人可从人员列表选择并确认 | 未来若仅允许登录人，移除切换入口；不等于新增岗位权限 |
| 合理推断 | 预览非强制，不等同扫码核验 | 是否“必须有正式文件才能报工”待确认，本版不拦截 |
| 合理推断 | 拍照必传单张，其他项选填 | 正式凭证数量、角度、大小和保留策略待配置 |
| 建议新增 | 正品减少导致超出累计时暂停整商品 | 需要确定负责人更正/冲销入口及审计流程 |
| 建议新增 | 数量变化要求重新核对 | 开发需原子读写与版本/并发检查，不能只依赖页面显示值 |
| 建议新增 | 保存提交时正品快照与追加记录 | 支持解释历史报工为何发生，不将数量更新改写为历史完工 |

尚需后续确认（不阻塞本次原型）：四类预览文件来源/版本/格式；预览缺失是否禁止报工；拍照正式凭证要求；正品减少后的纠错流程；退换货若存在“一件退换一件、净正品数不变但需要重做附加项”，应建立独立返工记录还是调整有效累计数。**净数量不变的替换件返工不在本版“正品增加后增量报工”模型内。**

### 6.4 开发沟通边界

正式实现建议以商品 ID + 项目 ID 定位任务；每次提交包含本次新增数量、实际处理人、凭证、唯一请求标识及数量快照。服务端校验项目配置、最新正品和累计数量，在同一事务中追加记录与更新累计，重复请求返回同一结果。

网络超时存在“服务端已成功、客户端未收到”的可能；正式系统需按请求标识查询结果后重试。本原型的失败开关专门模拟“确定未写入”，不承诺覆盖所有网络一致性场景。

初版验收的重点是：**扫对商品、看清应做、只报本次、累计不超、增量可续、四项可预览、记录可追溯。**
