# 第一版演示报工

入口为 `pages/login/index`，选择演示员工后进入 `pages/workbench/index`。原基础模板保留供学习参考。

## 使用步骤

1. 在微信开发者工具选择普通编译并重新编译。
2. 首页点击普通商品，或输入 DDEMO001 查询。扫码只识别这些演示商品的纯文本 ID，真实业务二维码格式尚待确认。
3. 选择演示员工，在贴纸项目输入 6，确认报工。
4. 剩余未报应为 4。再次输入 5 应被拒绝，输入 4 后显示已报齐。
5. 点击演示操作增加正品数，项目恢复部分报工且剩余 2。
6. 点击底部报工记录查看流水；人员产量按日期、人员和项目汇总，可点击下钻记录。
7. DDEMO002 用于无附加项场景，DDEMO003 用于正品为零场景。

## 数据边界

数据存于本机微信存储 `work-report-demo-v1`，模拟器与手机不共享。不接入生产，不计正式产量，不改变清算。不提供真实登录，员工选择仅为演示。贴纸、吊牌、洗标和 FBA 预览入口目前提示尚无文件，并非已实现真实文件预览。

本地服务有整数上限校验及请求去重，但不能保证跨设备并发一致性。正式版必须由后台完成鉴权、最新数量校验、事务保存、请求幂等和两端同步。设备日期仅供演示，正式统计使用后台确定的业务时间。

## 文件职责

- pages/workbench/index.wxml：页面结构。
- pages/workbench/index.wxss：页面样式。
- pages/workbench/index.js：交互与页面数据。
- services/report-store.js：演示数据、报工校验和统计，后续替换为后台接口。

## 验证

在仓库根目录运行 `node tests/report-store.test.cjs`。覆盖数量上限、非法数量、重复请求、不同员工统计、正品增加后补报、空数据场景及写入失败。

已完成 Node.js 逻辑验证和 JavaScript 语法检查。微信开发者工具编译、页面布局、手机扫码和触摸交互仍需在本轮代码上实测。

## 演示登录

选择演示员工 A 或 B 后进入工作台，默认带出实际处理人。工作台可退出登录，退出保留报工记录。演示会话仅驻留内存，重新启动需重新选择身份；不代表真实认证。新记录区分提交账号和实际处理人，允许切换处理人仅为演示，正式代报规则待确认。

验证命令：node tests/session.test.cjs。登录页面视觉、手机交互仍需在开发者工具和真机检查。
